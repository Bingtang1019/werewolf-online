# archive/v5-投票判定实验 —— V5 主干判定（路径 A vs B，2026-08-08）

> **性质**：架构判定实验归档（非模型文件）。结论：**路径 B（策略学习，无前瞻）成立**——狼人杀投票不需要前瞻，rollout 退役。
> **触发背景**：层级自举（三档全提 simulate_v2）后 12a 系统性偏狼 +22~30pp，归因发现 rollout"单视角模拟"是结构性缺陷。
> **2026-08-08 二次修订**：300 局配对 + 分侧覆盖审计后，归因修正（见第八、九节）——早期"43.1% vs 54.4%"为小样本直测假象，真值见下表。

## 一、归因结论（为什么 rollout 负增益）

| 证据 | 值（早期小样本） | 值（大样本真值，见第八节） |
|---|---|---|
| 好人侧 rollout 命中真相（投狼） | 43.1%（1572 票审计） | **49.1%**（1476 票，simulate 档） |
| decideVote 命中真相 | 54.4%（+11.3pp） | **61.5%**（+12.4pp） |
| rv≠dv 分歧率 | 36.5%（573/1572） | **34.6%**（510/1476） |
| 分歧票中 rv 更好 / dv 更好 / 都错 | 63 / 241 / 243（dv 4:1 碾压） | 大样本：dv 系统性优于 rv（-12.4pp） |
| rv 高 margin（≥0.3）仍错 | 大量（margin 机制无法兜底） | margin≥0.05 覆盖 94.3% 仍错（-12.4pp） |

**根因**：rolloutVote 模拟其他玩家投票用 **`world.scores`（当前 bot 自己的嫌疑分）**——假设"所有玩家共享我的视角"（单视角/独裁世界模拟）。现实是多 agent 异质（各自 scores + 卖狼/跟票/恋人红线/波动）→ 前瞻收益基于错误世界模拟 → 系统性投错目标。**这是模型错误，不是调参问题**。

**排除项（已实验证伪）**：价值模型视角（V_good/V_wolf/parse 均偏狼 68-77%）、符号反（修复后 68.0% 不变）、狼侧 rollout（去掉反而更偏 71.9%——但该对照为小样本，大样本见第八节狼侧审计）。

## 二、判定实验 1：投票预测器（路径 A 可行性）

**目标**：P(vote_i = j | 投票者视角, 候选集)——"别人会投谁"是否可学。

| 项 | 值 |
|---|---|
| 数据 | 999 局 12a（**vote_cast 逐票事件**，v2 生态 smart 档），33,168 票 / 277,839 样本对 |
| 特征 | voteFeatures 13 维公开信息（座位/发言/查杀声明/票型/自称/质疑/对跳/行为一致） |
| 模型 | MLP（hidden 64，BCE，按 botId 划分 80/20） |
| 泄漏修复 | 初版 100%（结算快照含后续票 + actionLog 含本次票）→ 逐票事件 + push 后置 → 51.6% |
| **预测器 top-1** | **51.6%**（全量 30 epochs） |
| 基线（投最高 votes_against） | 47.2% |

**口径审查（重要，防止误读）**：
- **51.6% 是"行为预测"口径**：预测对了**投票者实际投的人**（与真相无关——投票者可能投错人，预测对了他的错也算对）
- **54.4% 是"真相命中"口径**：**投中了狼**（与行为无关——decideVote 策略本身的质量）
- **两者不是同一测量，并排比较严格说不严谨**（一个是行为保真度、一个是决策质量）
- **但结论方向不受影响**：同质 bot 生态下，投票者的行为就是 decideVote 类策略的输出（行为克隆上限 ≈ 老师水平），实验 2 的 75.5% 输出保真补足了"可学性"证据——即"他人投票动力学"可学，但**学到的水平不超过现有启发式**（且成本高）。
- 未来引用这两个数字做对比时，必须注明口径差异（本段为强制引用注释）。

## 三、判定实验 2：BC from decideVote（路径 B 可行性）

**目标**：π(13维特征) → decideVote 输出（label = 审计的 dv——**纯规则策略输出，无 rollout 污染**）。

| 项 | 值 |
|---|---|
| 数据 | 500 局（vote_cast + rolloutAudit dv 标签按序对齐），92,770 样本对 |
| π(dv) top-1（输出保真） | **74.9%**（quick 75.5%，稳定；随机基线 9.5%） |
| 判定 | **✅ π 高保真克隆 decideVote 行为 → BC 有效 → 路径 B 可行** |

**语义**：75.5% = 候选集内正确选出"decideVote 会投的人"（行为克隆保真度）；decideVote 自身命中真相 54.4% 是 π 的**起点**（BC 只是初始化，PPO 微调后可超越老师）。

## 四、判定结论

| 路径 | 证据 | 判定 |
|---|---|---|
| **A**（VoteDynamics 修模拟失真，保留前瞻） | 预测器 51.6% < decideVote 54.4%（行为预测口径，见上）；动力学可学但强度弱于启发式；需 VoteDynamics + 重采 + 集成，成本高 | **否决** |
| **B**（策略学习 π(a\|s)，无前瞻） | π 高保真克隆 decideVote（75.5% 输出保真）；decideVote 是可靠老师（54.4%）；rollout 退役 → 性能 70 倍/超时结构性消失 | **✅ 成立** |

**战略结论**：狼人杀投票决策的正确形态是"**当前信念的正确运用**"（嫌疑分整合）而非"未来模拟"。前瞻（rollout）的模拟失真在狼人杀多智能体场景是结构性缺陷。

## 七、教训固化

- **数据泄漏两连**：结算快照泄漏后续票（→ 逐票事件）；actionLog 含本次票（→ push 后置）。**训练数据事件必须携带"决策时刻前"状态快照**，验收前先做特征均值对比（正负样本 Δ=1.0 的即泄漏）
- **口径纪律**：行为预测（投对实际目标）≠ 真相命中（投中狼）——不同测量不并排比较，模型卡强制注明
- **同质生态克隆上限**：bot 投票者 = 规则策略输出 → 预测器上限 ≈ 老师水平；"预测他人"与"克隆老师"在无真人对局时信息等价
- **小样本假象**（本次最重要的教训）：64 局功效 ±6-8pp，手动直测 rollout 裸输出（未经 margin 门控）——得出"43.1% vs 54.4%"的假象；300 局配对 + 覆盖审计修正为"49.1% vs 61.5%"。**归因结论必须大样本 + 生产链真实路径（含门控）**

## 八、归因修正（2026-08-08，三块证据补齐）

### ① 错误机制
早期"43.1% vs 54.4%"比较的是 **rollout 裸选择（未经 margin 门控）**——生产链中 margin<0.05 不覆盖。早期比较了一个"永远不会生效的分支"？**否**——大样本审计显示 margin≥0.05 覆盖 **94.3%**（rollout 并非被门控禁用，而是高自信地错）。早期错误在于**小样本（64 局）+ 手动直测口径**。

### ② 错误来源
- 64 局小样本（±6-8pp 功效，不可靠）
- 手动直测 rollout 输出（未经生产链路径）
- 早期"偏狼 68%"是**层级自举实验（LEVEL_MAP 全提 simulate_v2）的生态混淆**——smart 档被提到全链后行为变化，非 rollout 机制本身

### ③ 修正结论（300 局配对 + 覆盖审计）
- 好人侧 rollout 真值：**覆盖 94.3%（margin≥0.05），命中 49.1% vs dv 61.5%（-12.4pp）**——rollout 有害（非零贡献，是负贡献）
- 放宽阈值模拟（0.02/0.01）：覆盖略升（94.6-94.8%）命中不变（49.2%）——**无阈值可救**
- 当前生产链（smart 档 = useRollout=false）= **dv 全量**——12a 狼胜 47.7% **平衡**（"偏狼 68%"是层级自举实验的产物，已回滚）

### ④ 路径 B 判定理由修正
不是"rollout 有害"（负增益）→ 而是"**rollout 对好人侧是系统性负贡献**（-12.4pp）、对狼侧是正贡献（+8.5pp 投神职）"——**分侧管道**：好人侧 rollout 退役（π/dv），狼侧 rollout 保留。路径 B 依然成立，动机更纯粹。

### ⑤ 锚点修正
- **decideVote 真相命中大样本真值 = 62.6%**（早期 54.4% 同为小样本假象）
- **V5.1 验收锚点：62.6% +3pp**（信念引擎增益窗口以此为准）
- 早期所有引用 54.4% 的位置以上表真值为准（本文档已同步）

### ⑥ 狼侧分侧证据（大样本）
| 指标 | rv（rollout） | dv（decideVote） |
|---|---|---|
| 投好人率 | 100% | 100%（强制约束，无差异） |
| **投神职率** | **56.4%** | 50.3% |
| 分歧票（71.8%）投神职 | **57.3%** | 48.8%（+8.5pp） |

**分侧结论**：狼侧 rollout 有真实前瞻价值（投神职更准——狼知道队友 → 模拟失真小）；好人侧 rollout 系统性投错（-12.4pp）。**分侧管道决策确认**：好人侧 π/dv，狼侧 rollout 保留（V5.2 再考虑策略化）。

## 九、加噪判定实验（2026-08-08，视角多样性能否修复 rollout）

**动机**：0.6/0.4 同质化假设（所有 bot 共享嫌疑分公式+vote-v2 模型 → 决策空间坍缩）——检验"rollout 的失败是缺视角多样性"。

### 同质化机制（代码实锤）
- `bot-brain.js`：嫌疑分 = 0.6×信念 + 0.4×模型（**硬编码，所有 bot 同构**）
- `rollout.js` L273-289：模拟所有玩家投票用 `world.scores`（**bot 自己的嫌疑分**）——单视角模拟
- vote-v2 模型共享 → 同局面输出相似

### 实测 margin 分布（反驳"margin→0"推论）
| 分位 | 值 |
|---|---|
| p5 | 0.01-0.05 区间 |
| **p25-p95** | **≥0.1（92.6% 票集中在 ≥0.1）** |

**推论证伪**：margin 不趋近 0——rollout 高度自信（覆盖 94.3%），且与 dv 分歧 34.6%。"同质化 → margin→0 → 零覆盖"不成立；同质化的真实后果是**"模拟贴近现实 → 前瞻无新信息 → 收益≈直接决策"**（且结算偏差为净负）。

### 加噪实验（LAB_ROLLOUT_NOISE=σ，Box-Muller 高斯注入模拟投票的 sc）
| σ | rv 命中 | dv 命中 | Δ | 覆盖 | 分歧 |
|---|---|---|---|---|---|
| 0.00 | 49.1% | 60.8% | -11.8pp | 94.3% | 34.6% |
| 0.02 | 16.9% | 61.3% | **-44.4pp** | 66.6% | 90.6% |
| 0.05 | 14.0% | 58.5% | -44.5pp | 70.2% | 89.9% |
| 0.10 | 6.8% | 52.6% | -45.8pp | 81.5% | 86.5% |

### 判定：结果 B（rollout 退役闭环）
- **加噪雪崩式劣化**（-44pp）：视角多样性让模拟投票**更脱节**于现实（分歧 34.6%→90.6%），前瞻基于更失真世界
- **同质化不是病灶**：σ=0 时模拟最贴近现实（分歧仅 34.6%）——"单视角"在**同质生态**里是**最好的近似**
- **真正结论**：rollout 的问题不是"不够多样"，是"**前瞻在该决策结构下无价值**"（模拟≈现实 → 无新信息；引入偏差 → 净负）

### 架构影响
- **V5 路径不变**：好人侧 π 替代 + rollout 退役（结果 B 闭环）；狼侧保留（前瞻有信息优势）
- **0.6/0.4 硬编码**：仍列入 V5.1 学习式信念整合的替代清单（权重不该硬编码）——但理由修正为"信念整合该学习"，非"多样性调节"
- **门控保留**：LAB_ROLLOUT_NOISE 保留为诊断工具（未来生态变化（如真人局）时重测视角多样性的依据）

### 配置矩阵（待补：9a 及后续配置的 π 评估——V5.2c 配对终裁时全量入表）

## 十二、校准审计（审查点 2，2026-08-08）

### 结果：绝对后验校准 FAIL（max 桶偏差 85pp→45pp），但排序有效（AUC 0.60）+ π 增益真实
- **FAIL 机制**：log-odds 增量累积过冲（多证据叠加后后验推向 0.9+，实际狼率 10-14%）
- **修正**：输出层 rank 归一化（存活内排名→[0,1]，getBeliefs.ranks）——消除绝对过冲、保留排序信息
- **权重组合教训**：单证据方向可反（票型"被集火=嫌疑"单独反），组合后净正向（AUC 0.60）——**权重是组合调优问题，非单证据方向问题**（降档实验：0.6151→0.4111→0.49→0.40 全损，恢复组合后 0.6018）
- **π 增益机制确认**：信念特征增益（+5.5~7.5pp）来自排序信息（rank 归一化保留增益），非绝对校准——**增益真实，机制正确**
- **遗留**：绝对后验校准仍 FAIL——V5.2 学习式信念整合（critic/值头）将学校准（监督信号），替代手调权重

## 十三、技术修正：V5.2 critic 不能用 V4.2（输入同源纪律）

**V4.2 输入 = 全知视角（R/S/M 真实计数）——π 输入 = 玩家视角（嫌疑+信念）——GAE 优势估计要求 V(s) 与 π 状态同源。**
**修正**：critic 用玩家视角特征训练（监督：终局 0/1；输入 = 信念状态特征）——标准 actor-critic 形态（共享特征层 + 独立值头）。

## 十五、轻量版 B：多样化变体池（2026-08-08）

### 变体实现（per-bot 门控，生产默认零影响）
- BOT_SUSPICION_W / per-bot suspicionW：信念/模型混合权重（0.6/0.4 可配）
- FOLLOW_MODE / per-bot followMode：跟票规则（strict=默认前二跟票 / loose=前二独立 / none=最高嫌疑）

| 池 | π 信念 | dv | Δ |
|---|---|---|---|
| 同质池 | 60.2% | 63.2% | -3.0pp |
| 权重变体池（0.6/0.8/0.4） | 60.2% | 63.3% | -3.1pp |

1. **权重扰动（嫌疑分混合）无效**——同质生态下 vote-v2 共享模型，扰动后嫌疑排序几乎不变
2. **跟票规则变体有效**——决策逻辑级异质性产生真实生态变化（所有策略绝对命中率 +2.7~3.2pp）
3. **多样化是"涨潮"非"重新洗牌"**——π 获益（+3.2pp）但 dv 也获益（+2.7pp），未超越
4. **信号确认**：变体池是 RWR/PPO 的"有信号环境"（π 在变体池有增益空间）——RWR 应在变体池重跑（同质池失败 = 信号缺失，变体池信号存在）

## 十七、超时问题的架构解法（taskd + 分箱 AdaBoost——2026-08-08）

### 问题（9 次事故 ≈ 2 小时）
训练/采集 20-40 分钟 vs 执行窗口 120s——手动 spawn/轮询/日志反复出现：
超时杀进程（execFileSync 语义误用）、spawn 竞态（删临时文件过早）、
done 死锁（stall 局不写 done）、并发 OOM（96 worker）。

### 解法 1：taskd 任务守护进程（tools/taskd.js）
长任务移入常驻守护进程，工具调用只做"提交 + 查询"（秒回）：
  submit → 队列（data/tasks/*.json）→ daemon 顺序执行（max-procs 预算）
  status/wait → 窗口内查询
checkpoint 语义：任务自身断点续跑（run-batch done / 训练 merge），守护崩溃重启续。
实测：16 配置训练 40 分钟+9 次事故 → 6 分钟零中断。

### 解法 2：分箱 AdaBoost（train-vote-v3 --bins=8）
stump 搜索从"逐样本扫描"改"预计算箱索引 + 前缀和"：
  O(样本×阈值×特征) → O(样本×特征) 建箱 + O(箱×特征) 搜索
实测：150 树 6 万样本 240s → 4s（50 倍）；16 配置 40 分钟 → 6 分钟。
正确性：12a AUC 0.8503 → 0.8504（等价）。

### 教训
1. execFileSync timeout = 杀进程（不是放弃等待）——长任务必须 spawn detached + taskd
2. 临时脚本 spawn 后不能立即删（竞态）——用 node -e 内联
3. done 判定必须容忍 stall（-2 容差）——死锁预防
4. 并发预算：96 worker OOM → taskd max-procs 控制

## 二十四节：vote-v4 蒸馏事故（vote_share 语义错误 + wolf_kill 漏喂）——2026-08-09

> 事故类型：**数据源 bug 被 AdaBoost 容错掩盖、被 MLP 蒸馏炸出**——"能跑 ≠ 正确"的最完整案例。

### 事故链条

1. **vote-v3 在线采集期**（v3og，16 配置 × 800 局）存在两个隐蔽 bug：
   - **vote_share 特征语义写错**（bot-brain beliefFeatures25）：`room.votes` 是 `{投票者id: 目标id}` 映射（谁投了谁），代码却当计数表用——`room.votes[candId]` 取到"候选投给了谁"（目标 id 字符串）→ NaN → JSON 序列化为 null（45% 行）；目标 id 为数字时 → 巨大数（5.3e18/5.6e75）
   - **wolf_kill 事件漏喂信念引擎**（game.js 挂载处）：只喂 deaths/exile/vote_cast/claim 四类——`eng.kills` 恒空 → **death_infer 特征恒 0**
2. **vote-v3 用脏数据训练并上线验收通过**（+10.5~11.2pp 投狼率、16 配置配对、12c 回退）——**一切基于脏数据的结论全部作废需重验**（见下"深远影响"）
3. **vote-v4 蒸馏（MLP）时崩盘**：NaN 进 norm 计算 → mean[16]=9.9e70 → Spearman 0.81 < 0.95 FAIL

### 为什么 AdaBoost 掩盖、MLP 炸出

- AdaBoost stump：`features[st.f] < st.thr`——null 参与比较时 JS 转 0 → **有确定行为、不崩**
- MLP：输入进 norm（mean/std 统计）→ NaN/1e70 污染 → 训练崩
- **结论：NN/蒸馏 = 数据质量检查器——对输入分布敏感，能把容错模型掩盖的缺陷炸出来**

### 深远影响（全部基于旧 v3 的结论重验）

| # | 受影响结论 | 处理 |
|---|---|---|
| ① | vote-v3 验收（+10.5~11.2pp、16 配置、12c） | **重采重训后全重跑**——修复后可能更强（+12-15pp？）但行为会变，不能假设"修复=更好" |
| ② | 0.4/0.6 权重扫描（白捡 +4.2pp） | P(wolf) 分布变化后重扫 |
| ③ | 二十二节"嫌疑分层动态化否决" | 脏数据下做的——否决结论作废 |
| ④ | 新锚点（v3-dv 投狼率 65.4%） | 重训后作废，以新 v3 为准 |
| ⑤ | D1 信念引擎（AUC 0.61） | 死亡证据缺失下的成绩——wolf_kill 修复后**AUC 重测**（重采数据顺带验证） |
| ⑥ | v2 回退链的"当前票数"特征 | 低优先检查（v2 也用了 room.votes？回退链可靠性依赖它） |

### 修复

1. **vote_share 语义修复**（bot-brain）：统计候选被投数/总票数（`Object.values(votes).filter(t => t === candId).length / Object.keys(votes).length`）
2. **wolf_kill 喂入引擎**（game.js）：补事件类型（death_infer 数据源）
3. **验证**（重采 20 局）：f[16] 0 null/0 越界/5607 全 0-1；f[17] 0→284 非零；f[13] 负向更新正常（均值 0.297、min 0.06——方向修复后被投多→嫌疑-）

### 纪律（追加到 A-2 生态采集层）

**纪律 1：蒸馏/NN 训练 = 数据质量检查器**
> MLP 对输入分布敏感——训练前必须做**特征分布审计**（mean/std 合理性 + null 率 + 恒值检查）。AdaBoost 类容错模型掩盖的数据缺陷会在 NN 训练时炸出——**任何 NN 训练的前置门 = 特征分布审计**。

**纪律 2：特征语义验证进训练管线**
> vote_share 类"语义写错但能跑"的 bug 防复发——特征构造代码审查清单：
> - **映射 vs 计数**：`room.votes` 是映射（{voter: target}），不是计数表——"候选被投数"必须显式统计，不能 `votes[candId]`
> - **null 语义**：NaN → JSON null 是"计算错误"信号，不是合法值——特征审计必须查 null 率
> - **事件源完整性**：信念引擎的喂入事件类型清单必须与训练侧消费的事件清单一致（wolf_kill 漏喂同类——game.js 挂载处与 belief-engine applyEvent 的 case 清单对照）
> - **归一化合理性**：训练后检查 norm mean/std 是否在合理域（vote_share 应 0-1 均值；出现 1e70 = 数据污染铁证）

- **vote-v4 蒸馏前**：特征分布审计（24 节纪律）+ Spearman 门（0.95）——信念维度的弱信号会在 Spearman 上体现（若 <0.95 需评估是否信念特征拖累）
- **不建议**因 D1 弱而移除信念特征（vote-v3 的 +2.2pp 是实证）——信念引擎定位修正为"vote-v3 的弱补充特征源"，非"独立强判别器"

**v4（256 蒸馏版）不上线**——配对验收 FAIL（12a 狼 +11.7pp、9a +4.9pp，配对方向 2.5:1/1.5:1 偏狼）——退回 v3 保持生产。损失 = 1.5h 训练 + 配对时间（预案内）。

| 配置 | v3 狼胜 | v4 狼胜 | Δ狼 | 配对方向 |

### 容量扫描（Spearman 代理的平台期）

| hidden | Spearman | 决策区一致率（margin≥0.1） |
|---|---|---|
| 128 | 0.8128 | 92.2% |
| 256 | 0.7984 | 95.1% |

**容量不是瓶颈**——Spearman 卡在 0.80 平台（蒸馏的固有信息损失：MLP 无法完整复现 150 树 AdaBoost 的决策边界）。

### 关键教训：决策区一致率的盲区（框架修正的再修正）

决策区一致率（margin≥0.1 时 95%）**通过了代理门但配对 FAIL**——原因：

```
① margin 分桶按 v3 的 margin 衡量——"v3 认为显著的票"（≥0.1）v4 跟得上
② 但 64% 的投票轮 margin <0.1（v3 自己的常态模糊区）——这些票 v4 只有
   70% 一致（128 版）/ 70.4%（256 版）——系统性偏向另一侧
③ dv 的决策主力恰好在低 margin 区（候选间分数接近是常态）
④ 结论：决策区一致率必须按"v3 与 v4 的共同 margin"（min(m3,m4)）分桶，
   且低 margin 区（<0.05）的一致率要求应单独设门（≥85% 才配对上线的候选）
```

### 方法论沉淀（纳入二十五节验收纪律）

```
· 蒸馏验收：Spearman（全分布）≠ 决策区一致率（v3 视角 margin）≠ 配对（硬门）
· 代理门只淘汰明显差的——"95% 决策区一致"不构成上线理由
· 低 margin 区（<0.05）一致率是蒸馏质量的**隐藏指标**（配对前必须测）
· 概率域消费（v3-fast）保留为基础设施——未来 v4 版本（更高保真蒸馏/
  特征对齐）可复用，但**当前版本不满足上线条件**
```

### 保留资产

- `models/adaboost-vote-v4.json`（256 版，146.8KB）——保留作蒸馏质量参照
- `train-vote-v4.js` + softTarget 修复（mlp.js）——蒸馏管道已验证可用

## 三十节：验收通过 ≠ 已上线——“切换执行”制度化（2026-08-09）

### 事故

vote-v3（干净数据版 v3v2）验收链完整通过（二十五节：16 配置配对 + 12c 回退 + 权重 0.4 重扫），**但生产默认从未切换**——`model-loader L109` 默认值一直是 'v2'（v1.7.16 遗留），v3 靠 env 显式启用。验收通过后焦点转向 vote-v4 蒸馏 → 数据事故修复 → DynEns，“切换执行”被搁置了两个版本周期。

**漏切的确切位置**：二十五节“生产切换”只切了 `V3_MODEL_PATH`（模型文件路径），没切 `VOTE_MODEL_MODE` 默认值（模式开关）——路径与开关分离，只切一处不算切换完成。

### 修复（2026-08-09 执行）

- `model-loader L109`：默认值 'v2' → 'v3'（env 覆盖保留——VOTE_MODEL_MODE=v2 一键回退）
- L14-15 注释同步更新（回退链文档 v3 → v2 → v1 → heuristic）
- 12c 回退路由保持（getVoteModelV2 独立缓存——机制盲区特例）
- 回退链逻辑验证：mode='v3' 时 v3 损坏自动落到 v2 路径（L126 `mode === 'v3'` 分支）——三级回退完好

### 纪律（验收模板强制项）

```
验收链的最后一步从“报告完成”改为“切换执行”：
① 验收 PASS → 立即执行默认值切换（VOTE_MODEL_MODE 类 env 默认）
② 切换后冒烟验证（未设 env 时走新默认 + 回退路由确认）
③ 验收报告模板加“切换执行状态”字段：已切 / 待切 / 灰度中
   —— 状态 ≠ “已切” 的报告不视为闭环
④ 路径与开关分离的切换（如 V3_MODEL_PATH vs VOTE_MODEL_MODE）
   必须两处都改并交叉验证——只切一处 = 未切换
```

### 复盘

- 损失：+8-12pp 投狼率（v3 vs v2 的配对增益）晚落袋两个版本周期——纯流程损失（数据/模型/验收都就绪）
- 根因：验收报告没有“切换执行”字段——“验收完成”被当作“上线完成”——缺失的一步没有被制度覆盖
- 本节的本质：**把“上线”从隐含步骤变成显式步骤**——与二十四节（数据质量检查器）、二十八节（共同 margin 门）并列的第三条流程纪律

### 纪律 A：切换默认值 = 全部默认值读取点的同步（2026-08-09 追加）

**切换清单（v3 切换实测 5 个点，未来切换直接按此扫）**：

```
grep VOTE_MODEL_MODE 全部出现位置 → 枚举每个默认分支 → 逐个同步：
① model-loader L109  模式加载默认（v2→v3）✓
② bot-brain L635    12c 回退路由默认（12c 局用 v2 保护）——未同步 = 劣化配置保护失效
③ bot-brain L653    useModel 判定默认（语义一致）——未同步 = 防未来埋雷
④ bot-brain L681    权重选择默认（v3→0.4 最优档）——未同步 = +4.2pp 白捡增益悄悄丢失（最隐蔽）
⑤ game.js L77      belief-engine 挂载条件默认（=== 'v3' 严格比较）——未同步 = 引擎不挂载
                   → 25 维特征构造异常 → 生产全局 engine 超时（最危险）
```

- **严格比较 `=== '模式名'` 是默认切换的暗坑**：`process.env.X === 'v3'` 在未设 env 时恒 false，而 `process.env.X || 'v3' === 'v3'` 才是默认语义——所有消费点必须统一用带默认回退的写法
- “半切换”典型：模型路径切了、模式开关没切（路径/开关分离）；或模式切了、下游默认分支没切（权重/路由/挂载）——**收益丢一半或埋雷**

### 纪律 B：验收必须覆盖“生产默认路径”（2026-08-09 追加）

**本次 5 个 bug 为什么验收没发现**：lab 配对都是显式 `VOTE_MODEL_MODE=v3` 跑的——**生产默认路径（未设 env）从未被验收覆盖**。

- A-2 生态采集层纪律的扩展：**验收环境配置 = 生产默认配置**——不只数据同源，**配置也同源**
- 验收报告必须包含“未设 env 冒烟”项：未设任何模型 env 启动 → 新默认加载 + 回退路由 + 权重 + 挂载条件全链路验证
- 本次冒烟 12a 8/8 落盘无超时（修复后）就是“未设 env 冒烟”的执行样例——它抓到了 game.js 超时与权重 0.6 两个漏网

## 三十一节：DynEns 两个悬案裁决（2026-08-09，干净环境重验）

### 悬案 1：二十二节"嫌疑分层动态化否决"——干净环境重验确认（否决维持）

**背景**：原否决数据出自超时期 + 脏数据时代（vote_share 45% null + wolf_kill 漏喂）——双重不可信，重验。

**重验实验**（12a × 200 局 × 2 批，v3v2 + 0.4 基线，standard）：

| 配置 | 狼胜 | 好人投狼率 |
|---|---|---|
| 动态（dynamicWb——原生产默认） | 59.5% | 61.2% |
| **静态 0.4（LAB_DYN_W=0）** | **52.5%** | **67.4%（+6.2pp）** |

**结论：否决确认**（干净环境）：
- 动态函数 wb=α/(α+k·β) 在"低证据"时错误地让弱信念主导（alpha 小时 wb→1）——但 v3 模型分内含信念特征（f[13]），本身更强——双重消费 + 低证据时错误让权
- **静态 0.4 实盘最优确认**（与二十二节一致——原结论方向正确，只是数据脏）
- **附带发现**：生产默认曾是动态（LAB_DYN_W 默认启用）——"未经验收的默认"再次出现（三十节纪律 A 同型）——已修复：门控反转（LAB_DYN_W=1 才启用，生产默认静态 0.4）

### 悬案 2：价值域 Phase 0 诊断（V3.1 vs V4.2 分歧度）——集成否决

**诊断**（p16-12a-v2 数据，6412 样本，重放 state + 双模型打分）：

| 指标 | 值 | 裁决 |
|---|---|---|
| Pearson 相关 | 0.9533 | **> 0.8 → 集成无肉** |
| Spearman 相关 | 0.9544 | 同上 |
| V 方向一致率 | 99.6% | 几乎完全一致 |
| V3.1 AUC | 0.6002 | 略优于 V4.2（+1.9pp） |
| V4.2 AUC | 0.5813 | |

**结论**：
- **价值域集成（双模型混合）否决**——两模型高度同源（0.95），无互补空间
- 微信号：V3.1 判别力略优（0.60 vs 0.58）——但**无生产消费点**（价值域仅狼侧 rollout 消费，而狼侧用 V_wolf 非 V3.1/V4.2 好人版）——**价值域集成线关闭**
- 分层分布：balanced 90% / extreme 10% / mid 0%——分层无意义

### DynEns 方案终局裁决（两案皆否）

**动态化全面收尾归档（有数据的不做）**：
1. 嫌疑域：静态 0.4 最优（重验确认）——动态不实施 ✓
2. 价值域：集成无肉（0.95 相关）——混合不实施 ✓
3. σ 加权/局面分桶/学习式权重：全部取消（价值域无消费点 + 嫌疑域已证静态最优）
4. **DynEns 遗产**：0.6→0.4 权重切换（+4.2pp）+ 动态权重的实验门控框架（LAB_DYN_W/LAB_DYN_K——未来新模型可复用）
